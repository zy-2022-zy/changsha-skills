# 长沙移动系统集团驳回数据Skill

通过本技能目录的 `scripts/run.cmd` 调用程序。依据为《长沙移动报备系统操作流程.docx》中“集团驳回”报备结果导出及两张操作截图；业务细节见 [references/workflow.md](references/workflow.md)。

已在生产门户实测通过：2026-11-04 单日集团驳回导出批次 `2118179097720991746`，下载合并后 107284 条，与门户“数据总量”一致。

2026-11-05 批次 `2118192243965767681` 实测：门户"数据总量 / 已导数量"均为 108232，合并后也是 108232 条（真实端口 108222、局数据端口 10）。

## 使用

使用 EXE 安装包时，程序默认安装到 `%USERPROFILE%\.workbuddy\skills\长沙移动系统集团驳回数据Skill`，已内置 Node.js 和依赖，无需运行 `pnpm install`。根据本 `SKILL.md` 的实际位置定位 `scripts/run.cmd`，从任意工作目录都可用绝对路径调用；启动器会自动切换到技能目录，保证配置、登录缓存和导出状态都保存在同一位置。

以下命令示例在技能目录执行。开发源码方式首次运行才需要 `pnpm install --frozen-lockfile`、Node.js 20+ 和 pnpm；同一个启动器会自动使用源码运行方式。

浏览器支持两种运行方式：

- **云浏览器模式（推荐用于云端部署）**：在 `.env` 中配置 `BROWSER_CDP_URL`，程序通过 Playwright CDP 连接已经启动的远程 Chromium。运行 Skill 的电脑必须能够访问该地址。
- **本地浏览器模式（兼容旧方式）**：`BROWSER_CDP_URL` 留空，程序在本机启动 Chrome 或 Edge；可通过 `BROWSER_CHANNEL=chrome` 或 `msedge` 指定浏览器。

本地开发时，可通过 SSH 隧道把云端 CDP 转发到 `http://127.0.0.1:19222`，并保持隧道窗口运行。不要把 Chromium 的 CDP 端口直接暴露到公网。云浏览器模式不要求员工电脑安装 Chrome 或 Edge。

先打印日期和筛选计划：

```powershell
.\scripts\run.cmd export --date 2026-10-22
.\scripts\run.cmd export --start 2026-10-19 --end 2026-10-22
```

用户要求执行导出时，加 `--execute` 创建门户导出任务并等待下载：

```powershell
.\scripts\run.cmd export --date 2026-10-22 --execute
```

没有指定日期时，默认北京时间前一个周一至周五。运行前说明实际日期范围。该算法不包含法定节假日和调休，涉及假期时根据用户明确给定的日期传参；不要把该推算宣称为官方工作日历。用户只要求查看计划时不加 `--execute`。开发技能本身不授权登录生产系统或执行导出。

云浏览器模式下，程序优先复用云端已经打开的门户标签页，避免新建标签页导致 `sessionStorage` 登录状态丢失。首次登录或会话失效时，Agent 按以下阶段调用 Skill，员工不需要打开 noVNC：\n\n1. `login-start`：自动打开门户、填写手机号，并且只在唯一识别到“同意”协议复选框时自动勾选。\n2. 如果页面要求计算/人机验证，Skill 返回页面提示，由 Agent 转发给员工；员工在聊天窗口提供答案后，Agent 调用 `login-verify --answer <答案>`。程序不自动破解或绕过人机验证。若页面没有该验证输入框，`login-start` 会直接请求短信验证码。\n3. `login-verify`：自动填写员工提供的验证答案并点击获取短信验证码。\n4. Agent 在聊天窗口询问员工短信验证码，再通过标准输入调用 `login-submit --sms-code-stdin`；Skill 自动填写、提交并检查“端口上报管理”菜单。短信验证码不打印、不写入 `.env` 或状态文件。\n\n每个阶段都会重新连接同一个云浏览器，操作结束只断开 Playwright 连接，不关闭云浏览器、浏览器上下文或当前标签页。登录成功后业务命令复用现有会话。noVNC 仅用于故障排查，不作为员工日常登录入口。下载文件通过 Playwright 下载流保存到运行 Skill 的电脑上的 `DOWNLOAD_DIR`。

本地浏览器模式仍使用原有 `.runtime/` 中的登录缓存。云浏览器模式不会把云端 Cookie 或会话信息复制到员工电脑的 `.runtime/`。`LOGIN_PHONE` 只在本机 `.env` 中配置，不复用文档中的具体账号。不要上传、输出或分享 `.env`、`.runtime/`。

**当前并发限制：** 云浏览器是共享的单一浏览器实例，本次改造只支持单任务串行联调。现有 `filing.lock` 只能阻止同一台电脑、同一技能安装目录中的重复运行，不能阻止不同员工电脑同时连接同一个云浏览器。完成服务端全局互斥锁和任务队列之前，不要在多台电脑同时启动任务，也不要在 noVNC 中手动操作正在执行任务的页面。

## 续查与恢复

同一门户、同一日期范围再次执行会复用状态，已有批次只续查，已下载文件只重新核算。状态在 `reports/`。Excel 默认保存到 `D:\报备\集团驳回\查询日期\`，根目录和日期子目录不存在时自动创建。跨日范围使用 `开始日期_至_结束日期` 子目录。只给批次号且没有历史日期状态时按下载当天的北京时间分目录。`.env` 的 `DOWNLOAD_DIR` 可调整根目录。

```powershell
.\scripts\run.cmd results --date 2026-10-22
.\scripts\run.cmd results --batch-id 2110281444303654914
```

批次号示例仅用于展示参数格式，执行时必须使用本次实际批次号。若创建任务后未取得批次号，核查门户“批量导出结果查询”中任务名称为“驳回端口导出”、数据类别为“驳回端口”、创建时间及操作人员均符合本次操作的任务，然后显式指定完整批次号和原日期，将它绑定到待恢复的状态：

```powershell
.\scripts\run.cmd results --date 2026-10-22 --batch-id 2110281444303654914
```

不要自动选择列表首行，也不要用其他用户或历史批次（“真实端口”“导入失败数据”等任务名）的任务代替本次“驳回端口导出”任务。提交结果不确定时，不删除状态重跑、不自动重复点击“批量导出”。门户改变定位方式或没有提供预期确认框时，保留状态并核实页面；定位器集中在 `src/portal.ts`。

## 结果

向用户报告实际筛选日期、导出批次号、下载路径、业务工作表及实际数据条数。门户查询界面数量与实际导出数量可能不同，以下载文件为准，不把列表数量当成已下载条数。

## SEDP 上传文件

下载完成后，程序在同一目录自动生成 SEDP 上传格式文件，文件名后缀 `-SEDP需要上传的文档.xlsx`，表头固定为 `子端口 | 签名 | 报备结果 | 备注`：

- `子端口` 取门户导出的“端口”列，逐行原样带出。集团驳回结果里既有真实端口也有局数据端口，两者都要，不能只保留一种。
- `签名` 按要求留空。
- `报备结果` 固定为“失败”：集团驳回记录再次上传报备必然失败。
- `备注` 统一写“集团驳回”，不沿用门户的驳回原因原文。

转换只在驳回类型全部为“集团驳回”时进行；出现其他驳回类型或非数字端口时停止并报错，不做静默跳过。SEDP 转换失败不影响已下载的驳回结果，原因记在状态的 `sedpError` 里，可用下面的命令单独重试：

```powershell
.\scripts\run.cmd sedp --file 'D:\报备\集团驳回\2026-11-04\集团驳回-2118179097720991746.xlsx'
```

`--output` 可指定输出路径；`--no-sedp` 跳过自动生成。

门户按分片导出，一次批次会拆成多个 xlsx，程序逐个下载后合并（每个分片自带表头，合并时只保留第一份），分片文件在合并成功后删除。程序识别前 30 行中至少包含两个已知业务字段的表头，统计其后的非空行，不按端口去重。多张候选表、未知表头或非 XLSX 响应会报错，文件仍保留；检查实际结构后可显式指定单表表头行：

门户分片偶尔会在有效 ZIP 之后追加一段多余字节，使解析器按最后一个 EOCD 记录读取时失败（报 `Unsupported ZIP Compression method`）。程序按 ZIP 结构定位第一个自洽的中央目录并截断修复，数据行不会丢失；修复后的分片仍按原规则参与合并和计数。单个分片修复后仍不可用才会重下，连续 3 次失败才报错停止。

```powershell
.\scripts\run.cmd inspect --file 'downloads\集团驳回-实际批次号.xlsx' --header-row 1
.\scripts\run.cmd results --date 2026-10-22 --header-row 1
```

不把本流程扩展为重新上报、删除端口、代客户上传 SEDP、自动发送消息或 5G 导出。普通端口和视频短信按文档使用相同入口，不凭空增加未提供的类型筛选。

开发验证：`pnpm run typecheck`、`pnpm test`。本地模拟验证不能替代客户完成登录后的门户联调。
