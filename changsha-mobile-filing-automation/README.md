# 长沙移动报备网页自动化

这是一个基于 Playwright 的本地自动化工具，按《长沙移动报备系统操作流程》辅助执行：

1. 打开湖南移动行业端口实名校验登记系统；
2. 用户自行完成账号、计算题和短信验证码登录，脚本自动检测登录完成；
3. 进入“端口上报管理 → 端口信息报送 → 真实端口数据管理”；
4. 批量导入 `.xlsx` 文件；
5. 轮询“批量任务查询 → 批量导入结果查询”，下载结果；有失败数量时同时导出失败明细；
6. 按原始上传文件和失败明细生成 SEDP 结果文件：失败记录在前，成功记录在后。

## 重要边界

- 密码、短信验证码和计算题答案不会保存；如需自动填入登录手机号，可仅在本机 `.env` 配置 `LOGIN_PHONE`，该号码不会写入运行日志或发送到远端。
- 第一次登录和登录失效后的验证均需在浏览器中手工完成。
- 导入会改变业务系统数据，因此 `run` 默认不上传；只有追加 `--submit` 才会提交。
- 会话信息保存在 `.automation-profile/`，该目录已被 Git 忽略，请勿共享。
- 单文件状态保存在 `reports/<sha256>.json`，用于中断后继续查询，里面不保存账号、密码或验证码。

## 安装

需要 Node.js 20 或更高版本。

```powershell
pnpm install
pnpm exec playwright install chromium
Copy-Item .env.example .env
```

程序默认使用电脑已安装的 Google Chrome。也可在 `.env` 中填写 `BROWSER_CHANNEL=msedge` 使用 Microsoft Edge；如果不使用本机浏览器，则需要安装 Playwright Chromium。登录成功后，程序会将浏览器会话快照保存在 `D:\报备\运行状态\Chrome登录状态`，Skill 升级或重新安装后仍会复用；网站主动失效登录时才需要重新完成登录。

如需让登录页自动带出手机号，在本机 `.env` 增加一行：

```text
LOGIN_PHONE=13800138000
```

## 使用

先只验证登录和文件：

```powershell
pnpm start -- run --file "D:\data\待报备端口.xlsx"
```

确认文件无误后提交导入、等待结果并下载：

```powershell
pnpm start -- run --file "D:\data\待报备端口.xlsx" --submit
```

如果导入已提交但等待超时，可单独继续查结果：

```powershell
pnpm start -- results --file "D:\data\待报备端口.xlsx"
```

工具会在终端输出 JSON，包含总数、成功数、失败数，以及下载文件和最终 SEDP 文件的本地路径。

如果执行过程中网络中断或程序退出，使用相同命令重试时会读取状态文件并跳过重复上传，继续查询原批次；只有明确追加 `--force` 才会重新上传同一份文件。

### 阶段二：批量处理多个文件

可以传入一个目录，也可以重复传入多个 `--file`。程序只打开一次浏览器、只登录一次，并按文件串行处理；每个文件完成后都会立即保存状态和 SEDP 文件。

批量入口会在校验和上传前自动拆分超限文件。每个数据子文件均为 `.xlsx`，最多 5000 条业务数据且实际文件大小不超过 2 MB；程序只拆分第 7 行开始的数据，完整保留前 6 行模板、41 个字段及格式、“省份地市名称”辅助表，并按数据行保留嵌入图片和引用关系。拆分文件暂存在原文件目录下的 `拆分临时文件` 子目录。

先做批次预检（不会打开浏览器，也不会提交）：

```powershell
pnpm start -- batch --dir "G:\data\待报备文件"
```

确认预检结果后执行批量提交：

```powershell
pnpm start -- batch --dir "G:\data\待报备文件" --submit
```

也可以指定文件清单：

```powershell
pnpm start -- batch `
  --file "G:\data\A.xlsx" `
  --file "G:\data\B.xlsx" `
  --submit
```

批次状态保存在 `reports/batches/`，单文件状态仍保存在 `reports/<sha256>.json`。中断后使用相同命令即可断点续跑：已完成文件会跳过，已提交但未完成的文件会继续查询结果。只有明确追加 `--force` 才会重新上传整个批次。

### 业务目录模式

可以在 `.env` 中指定一个业务根目录，例如：

```dotenv
FILING_ROOT_DIR=D:\报备
PENDING_DIR=D:\报备\待报备
COMPLETED_DIR=D:\报备\已经报备
REPORT_RESULT_DIR=D:\报备\报备结果资料
```

程序会自动创建这些目录。业务人员只需要把原始 Excel 放入 `D:\报备\待报备`，然后执行：

```powershell
pnpm start -- batch --submit
```

不带 `--dir` 时，程序默认读取“待报备”目录。处理完成后：

- 原始文件归档到“已经报备”；
- 网站下载的成功结果用于归档到“已经报备”；
- 网站失败明细不再单独归档，作为中间数据与原始报备资料关联；
- 按 SEDP 导入模板生成的报备结果资料归档到“报备结果资料”，其中“签名”取自原始文件的“企业签名”；
- 处理失败或校验不通过的原始文件保留在“待报备”，方便修正后重试。
- 超限原始文件的所有拆分子文件均完成后，原始文件才归档到“已经报备”；任一子文件失败时原始文件继续留在“待报备”。

每次批量预检或报备都会在 `reports/run-log.ndjson` 追加一条中文运行记录，时间统一显示为北京时间 `yyyy-MM-dd HH:mm:ss`，包含批次号、文件名、数量、状态和错误摘要，便于审计和排查。

### 远端日志

如需将执行结果同步到远端日志服务器，在 `.env` 中配置 `REMOTE_LOG_URL`，可选配置 `REMOTE_LOG_TOKEN`。程序会发送任务状态、文件名、批次号、数量和错误摘要，不发送密码、验证码、Cookie 或 Excel 内容。远端日志不可用时不会阻断报备流程，程序会在本地输出告警并继续处理。

### 客户/智能体调用方式

如果不希望客户接触源代码，可以把程序作为本机服务运行，WorkBuddy 或其他智能体只调用 HTTP 接口：

```powershell
pnpm start -- serve
```

服务默认只监听 `127.0.0.1:8787`。客户不需要修改程序，只需要提交文件路径或文件所在目录：

```powershell
$body = @{
  files = @("G:\data\A.xlsx", "G:\data\B.xlsx")
  submit = $true
  force = $false
} | ConvertTo-Json

Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8787/v1/jobs `
  -ContentType "application/json" `
  -Body $body
```

接口返回 `jobId` 后，智能体轮询查询：

```powershell
Invoke-RestMethod http://127.0.0.1:8787/v1/jobs/<jobId>
```

也支持 `directory` 批量目录，以及 `uploads`（文件名 + Base64 内容）用于智能体直接转交附件。服务内部仍然只使用一个浏览器会话并串行处理，结果中的 `batchState.items` 会包含每个文件的成功数量、失败数量、下载文件和报备结果资料路径。

生产环境建议在 `.env` 设置随机 `SERVICE_TOKEN`。设置后所有接口都必须带 `Authorization: Bearer <token>`；服务默认不暴露到局域网，避免把带登录会话的浏览器控制能力开放给其他机器。

完整流程只需要提供一个原始上传文件。错误明细由网站处理完成后自动下载，程序不会要求你手工准备或传入错误文件：

```powershell
pnpm start -- run --file "G:\data\需要上传的文档.xlsx" --submit
```

如需对已经下载的错误文件重新生成 SEDP，才使用下面的恢复命令（`--errors` 和 `--output` 均可省略）：

```powershell
pnpm start -- generate-sedp `
  --source "G:\data\需要上传的文档.xlsx" `
  --errors "G:\data\下载下来的错误信息文档.xlsx"
```

## 校验与限制

- 仅接受 `.xlsx`。
- 网站接收的每个数据子文件实际大小不超过 2 MB、业务数据不超过 5000 条。批量入口会自动按这两个硬限制拆分，不能仅按预计大小切分。
- 拆分只处理第 7 行开始的业务数据；每个子文件完整保留前 6 行模板说明、第 2 行的 41 个字段及格式、“省份地市名称”辅助表、嵌入图片资源和引用关系。
- 如果某一条数据及其图片单独生成文件后仍超过 2 MB，程序会停止该原文件并提示压缩图片或附件，不会生成违规子文件。
- 本地预检会校验全部必填字段、局数据端口号段和使用范围、真实端口与局数据端口关系、端口重复关联、省市地市对应关系、手机号、姓名、证件类型、日期、服务类型、广告促销条件、是/否枚举和 100 字长度限制。
- “广告促销”必须填写广告营销类短信行业类别和商业性短信接收意愿类型；商业性短信接收意愿文件可留空。
- 省市地市标准名称使用随程序发布的 `resources/filing-validation-rules.xlsx` 中的参考表，不依赖待上传文件内的可编辑字典。
- 企业和个人真实性、局数据端口是否已登记、网关一致性及变更记录的不可变更字段，需要在门户或主数据系统继续核验；程序会在预检结果中明确提示。
- 门户升级后如出现“找不到菜单或按钮”，请在 `src/portal.ts` 中更新对应中文文本定位器。
